# Pass Manager — API

REST API for **Pass Manager**, a password manager being rebuilt as a
**zero-knowledge** application: vault items will be encrypted in the browser,
and the server will only ever store ciphertext.

> **Status: v2 in progress.** The project started in 2023 as a learning
> playground and is now being audited and rebuilt milestone by milestone.
> See [docs/ROADMAP.md](docs/ROADMAP.md) for the plan and progress.
>
> ⚠️ Vault data is **not encrypted yet** (milestone M2), and several endpoints
> are still unauthenticated (milestone M1). Do not store real secrets.

The web client lives in a separate repository (`pass-manager`).

## Tech stack

| Area | Choice |
|---|---|
| Runtime | Node.js 22 LTS, TypeScript 5 |
| HTTP | Express 4, helmet, cors, compression |
| Data | MongoDB 7, Mongoose 6 |
| Auth | JWT, bcrypt, Google OAuth 2.0 (Passport) |
| Validation | Joi (request bodies and environment) |
| DI | Inversify |
| API docs | OpenAPI 3 generated by tsoa, served with Swagger UI |
| Tooling | ESLint 9, Prettier 3, Jest 30, Docker |

## Getting started

### With Docker (recommended)

Requires Docker with Compose v2.

```bash
cp .env.template .env
# Set JWT_SECRET to a random value of at least 32 characters, e.g.:
#   openssl rand -base64 48
docker compose up --build
```

The API listens on <http://localhost:3000> (override with `API_PORT=4000 docker compose up`)
and Swagger UI is available at <http://localhost:3000/api/docs>.
Compose starts its own MongoDB, so `MONGODB_URL` from `.env` is ignored there.

### Local development

Requires Node.js 22 (`nvm use`) and a MongoDB instance.

```bash
npm install
cp .env.template .env   # then fill in MONGODB_URL and JWT_SECRET
npm run dev             # API with auto-reload + OpenAPI spec regeneration
```

## Configuration

All variables are validated at startup; the process exits with a list of
problems if anything is missing or malformed. See [.env.template](.env.template).

| Variable | Required | Default | Description |
|---|---|---|---|
| `MONGODB_URL` | yes | — | `mongodb://` or `mongodb+srv://` connection string |
| `JWT_SECRET` | yes | — | JWT signing secret, at least 32 characters |
| `NODE_ENV` | no | `development` | `development`, `test` or `production` |
| `PORT` | no | `3000` | HTTP port |
| `USE_PROXY` | no | `false` | Trust `X-Forwarded-*` headers from a reverse proxy |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | no | empty | Enable "Sign in with Google" when both are set |
| `S3_ENDPOINT_URL`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | no | empty | S3-compatible storage for uploads |

## Scripts

| Command | Description |
|---|---|
| `npm run dev` | Start the API with auto-reload and regenerate the OpenAPI spec on change |
| `npm run build` | Generate the OpenAPI spec and compile to `dist/` |
| `npm start` | Run the compiled API (`dist/src/index.js`) |
| `npm run typecheck` | Type-check the whole project |
| `npm run lint` / `npm run lint:fix` | Lint (and auto-fix) with ESLint |
| `npm run format` | Format with Prettier |
| `npm test` / `npm run test:coverage` | Run the test suite (with coverage) |
| `npm run swagger` | Regenerate `public/swagger.json` |

## Project structure

```
src/
├── domain/          # Entities, repository and use-case interfaces
├── application/     # Use cases, validators and application services
├── infrastructure/  # Mongoose models/repositories, config, Passport, S3
├── presentation/    # Express server, routers, handlers and controllers
├── ioc.ts           # Inversify container
└── index.ts         # Entry point and process signal handling
```

## API documentation

The OpenAPI 3 spec is generated from the controllers by tsoa into
`public/swagger.json` and served with Swagger UI at `/api/docs`.
All endpoints are versioned under `/api/v1`.
